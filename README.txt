    Данный проект создан для создания резервных копий баз данных на MsSQL и их копирования на сервер хранения.

    Состоит из двух своих частей - maker_part и keeper_part. Maker_part работает на сервере базы данных, keeper_part
на сервере хранения. Поэтому разделение по папкам здесь - условное. Для полностью корректной работы необходимы почтовый
сервер с imap, а также поднятый сервер RabbitMQ с настроенными очередями. Помимо прочего необходимо выполнить создание
пользователя в БД для всех действий, а также настройки на СХД для схемы:
----------------------------------------------------------------------------------
Сервер БД - R/W права на диск - СХД - R/O права при подключении - Сервер хранения.
----------------------------------------------------------------------------------
Диск должен быть отформатирован с файловой системой exFAT для максимально нативного подключения в Linux.

                                Описание идеи каждой из частей.
1. maker_part
Для каждой базы данных создается свой файл конфигурации, который хранится в модуле databases. В нем настраивается как
включение/отключение создания резервной копии, так и расписание создания, а также режим резервного копирования (на
текущий момент только default - создание, проверка резервной копии, отправка результата в RabbitMQ.) Далее необходимо
включить необходимые базы данных в переменной DATABASE_LIST файла .env, в том порядке в каком необходимо создавать
резервные копии. В этом файле также находятся различные переменные с комментариями, за что они отвечают. По итогу
всех действий отправляется отчет на электронные почты, указанные в переменной EMAIL_NOTIFY_LIST.
2. keeper_part
На сервере хранения в определенный промежуток времени происходит проверка очереди RabbitMQ. Если там есть сообщение,
то диск подключается и на основе информации в сообщении, сначала проверяет есть ли такой файл резервной копии. Если
есть, то начинается копирование в заранее определенную директорию на физический диск сервера хранения с помощью
утилиты rclone copyto. По завершению копирования информация отправляется на электронные почты, указанные в переменной
EMAIL_NOTIFY_LIST, и диск отключается.
